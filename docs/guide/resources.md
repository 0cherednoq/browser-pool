# Ресурсы хоста

Память, CPU и процессы браузеров под присмотром пула.

Скрипт оставили на ночь, а утром в диспетчере задач сорок процессов Chrome на 12 ГБ. Часть из них осталась от
запусков, которые упали или были прерваны Ctrl+C. Браузер, проработавший шесть часов, вырос до трёх гигабайт. Если
теперь добавить задач, система уйдёт в своп, и остановится всё, включая сам скрипт.

Пул сам следит за памятью, загрузкой CPU и процессами браузеров.

## Пороги памяти и CPU

```python
from browser_pool import BrowserPool, PoolConfig
from browser_pool.config import Lifecycle, Recycling, Resources, Topology
from browser_pool.drivers.playwright import PlaywrightDriver

config = PoolConfig(
    topology=Topology(browsers=4, pages_per_browser=6),  # жёсткий потолок: 4 Chrome, 24 вкладки
    resources=Resources(
        min_free_memory_mb=2048,
        max_cpu_percent=85,
        max_browser_rss_mb=1500,
        pressure_action="shrink",
    ),
    recycling=Recycling(browser_max_age=3600, browser_max_leases=500),  # плановый перезапуск
    lifecycle=Lifecycle(browser_idle_ttl=300, context_idle_ttl=600, page_idle_ttl=300),
)

pool = BrowserPool(PlaywrightDriver(), config=config)
```

| Поле секции `resources` | Что значит в примере |
|---|---|
| `min_free_memory_mb` | свободной памяти меньше 2 ГБ: новых браузеров и аккаунтов не открывать |
| `max_cpu_percent` | CPU выше 85% в среднем за 10 с: то же |
| `max_browser_rss_mb` | браузер толще 1,5 ГБ: перезапустить, дав доработать задачам |
| `pressure_action` | под давлением ещё и закрывать простаивающее |

:::{important}
Память и CPU замеряет psutil, для него нужна экстра `resources`. Без psutil секция `resources` игнорируется с
предупреждением в лог.

```bash
pip install --pre "browser-pool[playwright,resources]"
```
:::

## Что делает пул под давлением

Хост считается под давлением, когда свободной памяти меньше `min_free_memory_mb` или загрузка CPU выше
`max_cpu_percent`. В это время:

- новые браузеры и контексты не открываются, до `min_browsers` пул браузеры не добирает;
- уже выданные вкладки работают, открытые аккаунты обслуживаются, а новые заявки ждут в очереди и не падают;
- при `pressure_action="shrink"` пул ещё и освобождает память: закрывает тёплые вкладки, самый холодный контекст
  (сессия сохраняется) и браузеры без контекстов.

Когда давление уходит, пул снова растёт. О каждом переходе сообщает событие `ResourcePressure` (что давит, сколько
свободной памяти, загрузка CPU). Пока давление держится, его причина видна в `pool.snapshot().pressure`.

## Распухший браузер

Chrome со временем занимает всё больше памяти. Пул перезапускает браузер в двух случаях:

- по размеру - дерево процессов браузера занимает больше `max_browser_rss_mb`;
- по возрасту и пробегу - браузер прожил `Recycling.browser_max_age` секунд или отработал `browser_max_leases`
  аренд.

Перезапуск идёт с дренажом: браузер перестаёт получать новые задачи, выданные дорабатывают, сессии сохраняются,
браузер закрывается и запускается заново. Аккаунты после этого восстанавливают сессию без входа по паролю. Плановые
перезапуски идут по одному браузеру и только когда остальные здоровы, а пороги разбросаны (`recycle_jitter`), чтобы
браузеры не перезапускались одновременно.

## Простаивающее закрывается само

| Что | Закрывается через | Поле |
|---|---|---|
| тёплая вкладка без задач | 5 минут | `Lifecycle.page_idle_ttl` |
| контекст аккаунта без задач (сессия сохраняется) | 10 минут, 30 в `PoolConfig.accounts()` | `Lifecycle.context_idle_ttl` |
| браузер без контекстов | 5 минут | `Lifecycle.browser_idle_ttl` |

Когда приходит задача для закрытого аккаунта, контекст открывается снова с сохранённой сессией.

## Ни одного Chrome после остановки

Страж процессов (`ProcessGuard`) включён по умолчанию и работает в двух случаях:

- При `pool.stop()` (или выходе из `async with`) браузер, который не завершился после штатного закрытия,
  принудительно завершается вместе со всем деревом процессов: рендерерами, GPU, утилитами.
- Если процесс приложения умер, не успев ничего закрыть (`kill -9`, падение, выключили ноутбук), на диске остаётся
  реестр его браузеров. Следующий старт пула на этой машине завершает их и сообщает, сколько их было, событием
  `OrphansReaped`.

:::{note}
Процессы в реестре записаны вместе со временем создания, поэтому браузер чужой программы, получивший номер умершего
процесса, страж не тронет.
:::

## Задача, которая не отдаёт вкладку

Забытый `await` или зависшее ожидание держит вкладку бесконечно, и свободных вкладок в пуле становится всё меньше.

```python
from browser_pool import Limits

Limits(
    leak_warn_after=300,  # 5 минут
    lease_max_duration=900,  # 15 минут
)
```

Аренда дольше `leak_warn_after` даёт событие `LeakSuspected` со стеком места захвата. Аренду дольше
`lease_max_duration` пул отзывает принудительно: из `async with` вылетит `LeaseRevokedError`.

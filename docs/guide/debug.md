# Отладка окон

Все браузеры видны сразу, а упавшая вкладка остаётся открытой.

Скрипт на шесть аккаунтов открывает шесть окон Chrome в одной точке экрана, одно поверх другого, и видно только
последнее. Заголовок у всех одинаковый, поэтому непонятно, какое окно чьё. А когда задача падает, её вкладка
закрывается, и посмотреть, что было на странице, уже нельзя.

В режиме отладки пул раскладывает окна сеткой, подписывает их и оставляет упавшую вкладку открытой. Включается он
двумя секциями конфига: `windows` и `debug`.

## Окна сеткой

```python
import asyncio

from browser_pool import BrowserPool, Identity, PoolConfig, ProxyPolicy
from browser_pool.config import Debug, Topology, Windows
from browser_pool.drivers.playwright import PlaywrightDriver

accounts = [Identity(key=f"acc:{number}", proxy=ProxyPolicy.direct()) for number in range(1, 7)]

config = PoolConfig(
    topology=Topology(browsers=2, pages_per_browser=8, pages_per_identity=2),
    windows=Windows(mode="per_context"),  # окно на аккаунт, окна сеткой
    debug=Debug(label_windows=True, hold_on_error=60),  # подпись в заголовке, упавшая вкладка живёт минуту
)


async def read_quotes(lease) -> str:
    await lease.page.goto("https://quotes.toscrape.com/random")
    await asyncio.sleep(3)  # чтобы успеть посмотреть
    return await lease.page.inner_text(".text")


async def main() -> None:
    async with BrowserPool(PlaywrightDriver(), config=config) as pool:
        quotes = await pool.map(read_quotes, accounts * 2, concurrency=12)
        print(*quotes, sep="\n")


asyncio.run(main())
```

На мониторе 1920×1080 это выглядит так:

```
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ [acc:1] Quotes…  │ │ [acc:2] Quotes…  │ │ [acc:3] Quotes…  │
│  ┌tab┐┌tab┐      │ │  ┌tab┐┌tab┐      │ │  ┌tab┐┌tab┐      │
│                  │ │                  │ │                  │
└──────────────────┘ └──────────────────┘ └──────────────────┘
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ [acc:4] Quotes…  │ │ [acc:5] Quotes…  │ │ [acc:6] Quotes…  │
│  ┌tab┐┌tab┐      │ │  ┌tab┐┌tab┐      │ │  ┌tab┐┌tab┐      │
│                  │ │                  │ │                  │
└──────────────────┘ └──────────────────┘ └──────────────────┘
```

- Окна не перекрываются. Пул узнаёт рабочую область монитора (без панели задач), делит её на сетку с пропорциями,
  близкими к экрану, и ставит каждое окно в свою ячейку с зазором `gap` (8 px). Шесть окон на Full HD дают сетку 3×2
  с ячейкой 634×516.
- У аккаунта одно окно, а его задачи идут во вкладках этого окна. Две параллельные задачи `acc:1` открылись двумя
  вкладками в окне `acc:1`, а не отдельными окнами.
- В заголовке написано, чьё окно: `[acc:3] Quotes to Scrape`. Если у аккаунта есть прокси, рядом стоит его имя:
  `[acc:3 · de-1] …`.
- Окно занимает свою ячейку, пока не закроется (`reflow="stable"`): когда появляется седьмое окно или закрывается
  второе, соседи остаются на местах.
- Viewport страницы следует за размером окна (`fit_viewport`), а не остаётся 1280×720 с полосами прокрутки внутри
  маленького окна.

:::{note}
Отдельно включать видимый режим не нужно: пока окна включены, пул запускает браузеры с окнами. В проде достаточно
убрать секцию `windows`, и браузеры снова станут headless.
:::

## Окно на аккаунт или окно на вкладку

| Режим | Как выглядит | Когда удобно |
|---|---|---|
| `mode="per_context"` | у аккаунта одно окно, его параллельные задачи - вкладки внутри | следить за аккаунтами: «что сейчас делает acc:3» |
| `mode="per_page"` | каждая вкладка - своё окно в сетке | следить за всеми задачами сразу, когда у аккаунта их несколько |
| `mode="per_page"`, `group="identity"` | окна одного аккаунта стоят рядом, аккаунт - строка сетки | несколько задач на аккаунт и важно видеть их вместе |

```python
from browser_pool.config import Windows

Windows(mode="per_page", group="identity")  # аккаунт в строке, его вкладки в столбцах
```

:::{note}
Режим `per_page` работает с `PlaywrightDriver` на Chromium. Драйвер, который не открывает вкладку отдельным окном,
получает `per_context` и одно предупреждение в лог.
:::

## Какое окно чьё

`Debug(label_windows=True)` дописывает в начало заголовка окна ключ identity и имя прокси (`id` прокси или адрес без
логина и пароля): `[mail:42 · de-1] Входящие`. Подпись ставится скриптом страницы и сохраняется при переходах по
сайту.

:::{warning}
Подпись меняет заголовок страницы (document.title), и сайт может это увидеть. Используйте её только для отладки.
:::

## Упавшая вкладка остаётся открытой

Обычно упавшая вкладка сразу закрывается, потому что её состояние неизвестно. При отладке из-за этого остаётся только
traceback, а страницу, на которой всё сломалось, уже не посмотреть.

```python
from browser_pool.config import Debug

Debug(hold_on_error=120)  # упавшая вкладка не закрывается 2 минуты
```

Исключение уходит наружу сразу, код не ждёт. Вкладка при этом остаётся на экране `hold_on_error` секунд: можно
открыть DevTools, посмотреть разметку, сеть, консоль. Отпустить вкладки раньше можно вызовом
`pool.held_pages.release()`, а сколько их держится сейчас, показывает `pool.held_pages.held`. Задержанная вкладка
занимает слот, так что пул не выдаст вкладок сверх лимита.

В проде, где на экран никто не смотрит, ту же задачу решают улики: скриншот и HTML упавшей вкладки сохраняются в каталог
(`evidence_sink`, см. [Сбои и повторы](recovery.md#улики)).

## Замедление фоновых окон

Chromium экономит на фоновых окнах: таймеры в свёрнутом или перекрытом окне замедляются, анимации стоят. При отладке
кажется, что скрипт работает, только пока окно на переднем плане.

```python
Debug(keep_background_active=True)  # флаги Chromium против замедления фоновых окон
```

`Debug(slow_mo=250)` замедляет каждую операцию SDK на 250 мс, чтобы за кликами можно было уследить (если драйвер
умеет; Playwright умеет).

## Окон больше, чем помещается

Ширина окна Chrome не бывает меньше примерно 534 px, поэтому ячейка не меньше `min_size` (560×400). На Full HD помещается шесть таких
окон. Что делать с седьмым, определяет `overflow`:

| `overflow` | Что происходит |
|---|---|
| `minimize_idle` (по умолчанию) | простаивающие окна сворачиваются и отдают ячейку тем, кто работает; понадобилось снова - развернётся |
| `cascade` | лишние окна - лесенкой поверх сетки |
| `tabs` | лишние остаются как есть |

Другие способы поместить больше:

```python
from browser_pool import Rect
from browser_pool.config import Windows

# Два монитора: сначала заполняется первый, потом второй.
Windows(
    mode="per_context",
    screen=(
        Rect(x=0, y=0, width=1920, height=1040),
        Rect(x=1920, y=0, width=2560, height=1400),
    ),
)

Windows(mode="per_context", min_size=(540, 320), gap=4)  # мельче ячейка, плотнее сетка
Windows(mode="per_context", layout="columns")              # все окна в один ряд
Windows(mode="per_context", max_windows=4)                 # не больше 4 ячеек, остальное по overflow
```

## Управление окнами на лету

```python
await pool.windows.focus("acc:3")      # поднять окно аккаунта, свёрнутое развернуть
await pool.windows.minimize_idle()     # свернуть всё, что сейчас не работает
await pool.windows.retile()            # вернуть все окна в сетку
pool.windows.snapshot()                # какое окно в какой ячейке, чьё, занято ли
```

Окно, которое вы передвинули руками, пул не трогает до `retile()` (`respect_manual=True`). Одно окно можно развернуть
на весь экран, остальные продолжат работать в сетке. О каждом размещении окна сообщает событие `WindowPlaced`.

## Ограничения

- Окна нужны только для отладки. Сбой оконной операции попадает в лог и не становится исключением: раскладка не
  роняет задачу.
- С `PlaywrightDriver(headless=True)` или на Linux без `DISPLAY` окон нет, и секция игнорируется с одним
  предупреждением.
- Playwright двигает окна через CDP, поэтому раскладка работает только на Chromium, без Firefox и WebKit. У
  `PydollDriver` доступен только режим «окно на аккаунт».
- Все поля описаны в [справочнике конфига](../reference/config.md), секции `windows` и `debug`.
